# End-to-end tests in a real browser

Date: 2026-11-11 · Tier: Feature · Branch: `e2e-tests` · Status: design

Closes gap 3 of `docs/ENGINEERING_BASELINE.md` (B3, and the privacy half of B4).

## 1. Brief

- **Who and what problem:** The founder, and every later change to Anspruch. The main journey
  (welcome → situation → questions → report → PDF), resuming a saved intake, erasing it, the
  Arabic right-to-left interface and the promise that no answer leaves the device are checked
  only by hand (`.orchestration/runs/2026-10-22-live-test-fixes/`, the unticked list in
  `docs/DEPLOY.md`). 348 unit tests cover the engine, but nothing renders a component, so a
  wiring break between the engine and the screens reaches families unseen.
- **What they do today:** Click through the app by hand before a release, sometimes.
- **What changes for them:** Every pull request runs the main paths in a real browser against
  the production build, and a failure blocks the merge through the existing required check.
- **Business rule, in plain words:** A change that breaks the journey, the saved-answer
  handling, the right-to-left layout or the no-network promise cannot merge.
- **Out of scope:** Voice input and read-aloud (needs a microphone and speech engines a headless
  browser does not have; stays manual). The content of the PDF beyond "it is a real PDF" (gap 4,
  unit tests on `lib/report/pdf.ts`). Performance budgets (gap 6). Any change to app code,
  except a test hook if one proves unavoidable, which would be named here first.
- **Who must not be able to do this:** Not applicable; no roles. The privacy promise is the
  access rule: with analytics unset, no third party receives anything.

### Acceptance criteria

- [ ] AC1: In German, one question per screen, a run from Start through every question to
  "Ergebnis anzeigen" shows the report with a Pflegegrad (or a range) and the "asked N of 64"
  line, with no console error on any screen.
- [ ] AC2: Choosing العربية on the welcome screen sets `<html lang="ar" dir="rtl">`, the
  questions show in German or English (never Arabic), and the run still reaches the report.
- [ ] AC3: "Ergebnis jetzt schon anzeigen" after the first question shows a range, not a single
  grade, and "Weitere {n} Fragen beantworten" returns to the first unanswered question.
- [ ] AC4: "Als PDF herunterladen" on the report produces a download whose file name ends in
  `.pdf`, whose bytes start with `%PDF`, and the page shows "Gespeichert als …".
- [ ] AC5: After some answers, a reload shows the resume offer. "Weitermachen" returns to the
  same screen with the answers kept. "Neu anfangen und Antworten löschen" removes
  `anspruch.session.v1` from local storage.
- [ ] AC6: "Jetzt löschen" on the report removes `anspruch.session.v1`. A further change on the
  report does not write it back, and a reload shows no resume offer.
- [ ] AC7: With analytics unset, a full run through to the PDF makes no request to any origin
  other than the app's own, and sets no cookie.
- [ ] AC8: `/impressum` and `/datenschutz` load with status 200 and show their heading.
- [ ] AC9: At a 390 × 844 phone viewport the main path completes, and the Continue button is
  inside the viewport on every question screen without scrolling.
- [ ] AC11: axe finds no serious or critical violation on the welcome screen, a question screen
  and the report, in German and in Arabic.
- [ ] AC10: CI runs these tests on every pull request inside the existing required check
  "Lint, typecheck, test, build", so branch protection needs no change.

### Assumptions (not yet confirmed)
- The answers chosen in the tests are fixtures, not claims about any real household.
- Tests address controls by their visible German text and roles, the way a person finds them,
  so a copy change in `lib/i18n/strings.ts` can break a test. That is accepted as the price of
  testing what people see; the fix is updating the test with the copy.

## 2. Design

- **Stack and fit:** `@playwright/test` 1.64.1 (released 2026-10-14), exact pin, dev dependency
  only. Tests in `e2e/*.spec.ts`, config `playwright.config.ts`. Playwright's `webServer` runs
  `npm run start` on the build CI has already made, as the Next.js guide recommends ("run your
  tests against your production code"). Vitest keeps `lib/**/*.test.ts`; its include pattern is
  checked so it does not pick up `e2e/`. New npm script `test:e2e`. If axe is chosen:
  `@axe-core/playwright` 4.14.0 (released 2026-10-15), exact pin.
- **Docs read:** `node_modules/next/dist/docs/01-app/02-guides/testing/playwright.md` (Next
  16.4.2). Playwright's own docs for `webServer`, `waitForEvent('download')` and request
  interception are read for 1.64 before the build step that uses them.
- **Data:** None. Tests use a fresh browser context each, so local storage starts empty.
- **Flow:** CI job: install → lint → typecheck → unit → build → install Playwright browsers →
  start the built app → run `e2e/` → upload the HTML report and traces as an artifact on failure.
- **Failure:** A flaky test is fixed, never retried into green. CI uses `retries: 0`, with
  traces kept on the first failure so it can be read. Timeouts: 30 s per test, the default.
- **Security** (`/secure`, block 2a below).
- **Risks and rollback:** The CI job gets slower, by an estimated 1–3 minutes (measured in
  Evidence). Tests tied to copy can break on wording changes. Rollback: revert the merge; the app
  code is unchanged, so nothing reaches families either way.
- **ADRs written:** none. Choosing a test runner fits under this record; it does not bind
  product architecture.

| Flag | Abuse case | Control | Enforced where |
|---|---|---|---|
| Dependency | A compromised Playwright release runs code in CI | Exact version pin at least two weeks old, `npm ci` from the lockfile, `contents: read` token, no secrets in the job | `package.json`, `package-lock.json`, `ci.yml` |
